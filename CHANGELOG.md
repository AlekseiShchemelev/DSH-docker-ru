## [v0.2.3] - 2026-10-10

### 🔼 Адаптация ядра
- **Встроенная версия DSH обновлена до `@deepseek-ai/dsh@0.2.1-alpha.2`**: `supply.dshVersion`, параметр сборки Dockerfile `DSH_VERSION` и базовый заводской ориентир в `build.sh` синхронно обновлены до `0.2.1-alpha.2`.
- **Обновлена матрица совместимости**: `compatibility.adaptedVersions` в топ добавляет `0.2.1-alpha.2`, верхняя граница диапазона поддержки синхронно расширена до `<=0.2.1-alpha.2`, рекомендуемое ядро синхронно указывает `0.2.1-alpha.2`.
- **Осведомлённость консоли и шлюза о версии**: локальная инженерная версия в `gateway/version-service.js` повышена до `0.2.3`; резервные матрицы версий `dsh-manager.js`, `version-service.js` и панели управления синхронно в топе указывают `0.2.1-alpha.2`, устранено предупреждение консоли об отсутствии адаптации.
- **Инженерная версия повышена**: инженерная версия в `gateway/package.json`, `build.sh` и `.github/workflows/docker-build.yml` синхронно повышена до `0.2.3`.

### 📦 Пользовательские изменения официальной 0.2.1-alpha.2
- **Усиление аутентификации браузерных сессий**: проверка источника по authority запроса и белому списку `trustedHosts`, для TLS-прослушивания включены Secure Cookie и определение https-источника (в `isAuthenticated` добавлена семантика `secure`).
- **Экспериментальный постоянный терминал**: добавлены шесть глобальных инструментов терминала и набор терминальных композиций, shell-сессия сохраняется при вызовах между инструментами (по умолчанию выключено).
- **Рабочее дерево Git**: добавлены инструмент `create_worktree` и набор рабочих деревьев во время выполнения, одним вызовом создаётся и открывается изолированный каталог checkout (по умолчанию выключено).
- **Инструменты и среда выполнения рабочего каталога**: чтение или переключение каталога текущей Session, при воспроизведении сессии можно вернуться в выбранный каталог.
- **Поиск по сессиям и заголовки сессий**: добавлен инструмент только для чтения по истории сессий и поставщик заголовков, автоматически обновляющихся по мере развития диалога (по умолчанию выключено).
- **Машинный перевод процесса рассуждений (CoT)**: добавлены служба translator и клиентский UI, по умолчанию Bing, оригинал и сохранённый перевод сохраняются.
- **Экспериментальные наборы**: добавлены наборы навыков-значков DSH и цикла Ralph (по умолчанию выключено).

### ⚠️ Несовместимые изменения официальной 0.2.1-alpha.2
- **Снятие с поддержки пакетов hooks / webhook**: удалены `dsh-hook-protocol`, `dsh-hooks-claude-code`, `dsh-hooks-codex`, `dsh-webhook`, `dsh-webhook-github` и `dsh-subagent-in-process-driver`.
- **Изменение структуры типов `dsh-subagent`**: добавлены модули `activation` / `manager` / `structured`, удалены `continuation` и `continuation-activation`.
- **Полная перепаковка фронтовых ресурсов dist**: хэши файлов bundle изменены.

### 🛠️ Снимки и резервное копирование (Issue #9)
- **Выбор диапазона восстановления из снимка**: в консоли у «Восстановления» появилось двухпозиционное окно выбора диапазона — `⚡ Восстановить только конфигурацию` (текущие сессии и данные сохраняются) или `📦 Полное восстановление`; контекстные значения по умолчанию подбираются с учётом состояния текущих сессий, если сессии есть — значение по умолчанию не подставляется, требуется явный выбор с предупреждением о риске перезаписи. На бэкенде `POST /api/snapshots/restore` поддерживает `mode` (по умолчанию `full`, обратная совместимость), добавлено чтение-только `GET /api/snapshots/inspect`; критерии на стороне создания и восстановления унифицированы, для режима «только конфигурация» список исключений расширен до `storages`/`plugin-data`/`logs`/`cache`, чтобы `workspace.json` из старых снимков не перезаписывал индекс текущих сессий.
- **Полностью автоматическое восстановление снимков старых версий**: достаточно нажать «Восстановить» в консоли — относительные символические ссылки, «выходящие за пределы корня архива», в старых снимках исправляются автоматически (только для целей из существующего белого списка, остальное — fail-closed), дополнительные действия не нужны; таймаут ожидания запроса восстановления на фронтенде увеличен с 180 с до 600 с.
- **Исправлена ложная тревога SSE при длительных задачах**: при переключении версии ядра / восстановлении на месте используется канал с таймаутом простоя 60 с и добавлен заголовок `X-Accel-Buffering: no`, после обрыва потока состояние подтверждается опросом, что устраняет прерывание длинных задач общим таймаутом 20 с и ложное сообщение «Ошибка связи: signal timed out».

## [v0.1.9] - 2026-09-25

### ☁️ Облачная динамическая матрица совместимости и онлайн-переключение без обновления образа
- **Развязаны «обновление ядра DSH» и «обновление контейнерного проекта»**: когда официально выходит совместимая минорная версия, сопровождающему достаточно обновить `version.json` на GitHub — работающий контейнер сразу это замечает. Консоль **полностью устранила ложную тревогу «Рекомендуется в первую очередь обновить Docker-образ» для уже адаптированных версий**, пользователь переключается онлайн за секунды прямо на веб-странице, не скачивая заново многомегабайтный образ.
- **Динамические метаданные как единый источник истины**: в `gateway/version-service.js` добавлен `getLiveMeta()`, который в первую очередь читает живые метаданные GitHub / CDN и внедряет их в ответ запроса, а при офлайне/таймауте аккуратно откатывается на локальный заводской ориентир; в `gateway/dsh-manager.js` отменено единоразовое статическое чтение при старте, подключена живая матрица совместимости.
- **Осведомлённость консоли о статусе и источнике**: в центре версий добавлены динамические значки «`☁️ Облачные правила адаптации синхронизированы в реальном времени`» и «`📦 Локальные офлайн-правила`»; выпадающие списки и окно переключения точно показывают зелёный статус «`✔ Глубокая адаптация официальной версии · образ обновлять не нужно`» в зависимости от состояния адаптации.
- **Глубокая блокировка высокоопасных несовместимых мажорных версий (уровень Danger)**:
  - фронтовая консоль при `>=0.2.0` и других версиях с глубокой переработкой отключает кнопку «Подтвердить переключение» и даёт чёткие рекомендации о рисках;
  - бэкенд-интерфейс `/api/dsh/install` дополнительно выполняет предварительную проверку уровня `danger` и сразу возвращает 400, блокируя операцию, чтобы из-за ошибки не повредить контейнер.
- **Исправлена неработающая автоматическая GC хранилища версий (исправление C1)**: в `dsh-manager.js` после успешного переключения блокировка состояния `installing` не снималась заранее, из-за чего автоматическая LRU GC падала с исключением, которое молча подавлялось.

### 🔼 Адаптация ядра
- **Обновлена версия, встроенная в образ**: `supply.dshVersion`, параметр сборки Dockerfile `DSH_VERSION` и базовый заводской ориентир в `build.sh` синхронно обновлены до `@deepseek-ai/dsh@0.1.7-rc.2`.
- **Обновлена матрица совместимости**: `compatibility.adaptedVersions` официально включает `0.1.7-rc.2`, рекомендуемое ядро и диапазон поддержки расширены до `<=0.1.7-rc.2`, полностью поддерживаются динамические обновления инструментов апстрима (Dynamic Tool Updates), перехват файловых блокировок (Lock Takeover) и механизм усыпления плагина планирования по умолчанию.

### 🛠️ Управление точками отката движка и восстановление на месте в консоли (Issue #7 завершён)
- **Однослотовая точка отката на месте под защищённым сохранением**: после успешного переключения и пройденной проверки работоспособности заменённое предыдущее ядро **больше не удаляется автоматически**, а повышается до единственного слота-запасной части контейнера `.dsh-rollback-preserved` (не персистентно, остаётся в записываемом слое контейнера, новые точки монтирования не создаются). При следующем переключении старая запасная часть атомарно заменяется только после успешной проверки новой версии, в слоте всегда хранится ≤1 копия.
- **Защита от ложного удаления и самовосстановление при запуске**:
  - правила очистки `scripts/entrypoint.sh` и `cleanupStagingOrphans` явно исключают `.dsh-rollback-preserved`, чтобы не удалить вручную сохранённую запасную часть старше 60 минут; временный каталог подмены переименован в `.dsh-rollback-tmp-*` и по-прежнему чистится по истечении 60 минут;
  - при запуске контейнера, если активное ядро отсутствует, сначала выполняется восстановление из `.dsh-rollback-tmp-*`, а если его нет — самовосстановление из `.dsh-rollback-preserved`; спасение важнее сохранности.
- **Защитный барьер по ABI и архитектуре Node**: в `_restoreFromRollbackDir` и в процесс восстановления добавлена строгая проверка метаданных ABI/архитектуры; если окружение не соответствует запасной части, восстановление отклоняется с понятной ошибкой, что исключает запуск несовместимого ядра и его падение.
- **Отмена на месте за секунды и безопасная семантика восстановления**:
  - добавлена `restoreRollbackPoint()`: сначала запасная часть безопасно копируется (не rename, не жёсткая ссылка — перезапись не повредит оригинал) в изолированный staging, затем путём подмены каталога текущее ядро помещается во временный каталог, после чего выполняется адаптация плагинов и проверка работоспособности;
  - после успешной проверки текущее активное ядро автоматически становится новой защищённой точкой отката (естественно поддерживается повторная отмена); при неудаче выполняется безопасный откат к прежнему активному ядру, исходная точка отката остаётся нетронутой.
- **Серверный API управления**:
  - `GET /api/dsh/rollback`: получение состояния точки отката (версия, объём, время создания, соответствие ABI, возможность восстановления и т. д.);
  - `DELETE /api/dsh/rollback`: ручная очистка точки отката для освобождения диска (во время переключения — 409, при отсутствии — 404);
  - `POST /api/dsh/rollback/restore`: потоковое восстановление на месте по SSE (выводит индикатор прогресса и журнал выполнения в реальном времени).
- **Отображение на панели «Снимки и резервные копии» Web-консоли**:
  - добавлена отдельная карточка «🛠️ Точка отката ядра (системная запасная часть)», полностью развязанная с пользовательскими снимками на 17 КБ;
  - при наличии показываются версия, объём, время и значок ABI, доступны две операции — «`⚡ Восстановить эту версию`» и «`🗑️ Очистить точку отката`»;

### 🔁 Изоляция версий и переключение обратно без скачивания (Issue #7)
- **Исправлена проблема «для возврата на старую версию её нужно скачать заново»**: каталог архивов версий перемещён из записываемого слоя контейнера `/app/.dsh-versions-cache` на постоянный том в `$DSH_SNAPSHOTS_DIR/versions` (по умолчанию `/root/.dsh-snapshots/versions`, **повторно используется существующий монтирование `./data/snapshots`, новые точки монтирования не создаются**), после пересоздания контейнера / обновления образа архивы сохраняются. Пользователям, нуждающимся в полной изоляции, можно направить `DSH_VERSIONS_DIR` на собственный том.
- **Архивирование движка стало «выбором пользователя»**: в окно перед переключением добавлен флаг «Архивировать текущий движок (около 477 МБ)», **включён по умолчанию, но его можно отменить**; при отмене система больше не архивирует в фоне (ни при скачивании новой версии, ни после успешного переключения). При включённом флаге позднейший возврат на эту версию возможен без скачивания.
- **Откат больше не зависит от архива**: на время переключения сохраняется точка отката исходного движка и очищается только после успешной проверки работоспособности; при неудаче **восстановление выполняется локально за секунды из точки отката** (без сети и без архива), поэтому «снятие флажка архивации» не ослабляет защиту от аварийного отключения.
- **Устранена схема «сначала удалить, потом скопировать»**: переключение ядра выполняется как «копирование в изолированный staging → подмена каталога», любая ошибка I/O не оставляет контейнер без рабочего ядра; перед подменой процесс DSH останавливается.
- **Совместимость с overlayfs**: каталоги в слое только для чтения образа (lower layer) нельзя `rename` (ядро возвращает `EXDEV`), поэтому при подмене происходит автоматический переход на «копирование + удаление», проверено на реальном контейнере.
- **Маркер целостности `.ready`**: архив считается пригодным только при наличии `.ready` (версия / ABI Node / архитектура / число файлов / объём / ревизия образа), полукаталог, оставшийся после прерванного `cp`, больше не считается «закэшированным» и не разворачивается.
- **Устранены молчаливые сбои**: во всех `cp`/`mkdir`/`ln` теперь проверяется код возврата, при ошибке больше не печатается «✔ Восстановление за секунды завершено».
- **Добавлено управление хранилищем версий**: сохранение по LRU (по умолчанию 3 копии, активная версия и заводской ориентир образа защищены), предварительная проверка дискового пространства, `GET /api/dsh/versions/stats`, `POST /api/dsh/versions/gc`, `DELETE /api/dsh/versions/:version`.
- **Самовосстановление при запуске**: entrypoint при отсутствии активного ядра восстанавливает его из точки отката и удаляет просроченные остатки staging/rollback; без смонтированного постоянного тома выводится явное предупреждение.
- **Исправление формулировки**: из окна переключения версий убрано несбыточное обещание «< 1s».

### 📦 Метаданные версии в снимке конфигурации и отслеживание окружения
- **Инъекция метаданных версии в снимок и механизм Sidecar**: при создании снимка конфигурации автоматически фиксируется точная версия ядра DSH текущего окружения (например `0.1.7-rc.2`) и инженерная версия набора (`0.1.9`); скрытый Sidecar-файл атомарно записывается на диск (`SNAPSHOTS_DIR/.<filename>.meta.json`), что позволяет без распаковки извлекать версию и поколение структуры конфигурации за O(1).
